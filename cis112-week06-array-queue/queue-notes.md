**One addition to the library.** `hblibDatastructures.sty` has a new macro,
`\hQueueArray{capacity}{head}{tail}{size}{elements}`, with a version bump to
`v20261023T1345`. The old `\hQueue` draws the elements from index 0, so it cannot show a
queue that has wrapped; `\hQueueArray` takes the elements in **queue order** and places them at
`(head + k) mod capacity`, with `head` yellow, the free slot at `tail` green, the elements red
and a light-green `h`/`t` box when the queue is empty. It also handles the case
`head == tail` with `size == capacity` (a full queue). The old `\hQueue` is unchanged; the
stack and string decks still compile (checked `stack-0-concepts` and `String-1-concepts`).

**A deck-local listing setting.** Every queue deck has `\lstset{columns=fixed}`. With the
library's `columns=fullflexible`, the aligned columns of `printf` output (and, in a box after
another code box, even ordinary spaces) were stretched to the width of the box. Fixed columns
keep the character grid of code and output intact.

**Real output.** Every program output is real, from JDK 24 on macOS, and is regenerated by
`bash run_examples.sh` in each deck folder. What changes from run to run:
- the benchmark times (`Bench.txt`) and the BFS times (`BfsPerf.txt`);
- the producer/consumer and Michael--Scott times;
- the number of 8 KB arrays before `OutOfMemoryError` (about 2,850 with `-Xmx24m`).
The slides only claim what held in every run. The junior deck labels its table "on this
machine" and says that the order of the last four implementations may change.

**The benchmark, as it came out.** `int[]` is clearly the fastest (about 3.6 ns/op here);
`ArrayDeque` (about 4.3) beats `LinkedList` (about 5.9); our `LinkedQueue` (about 5.0) sits
between them, and `ArrayQueue<Integer>` (about 6.0) pays for the boxes. The lesson on the slides
is "measure, do not guess", not "arrays are always faster".

**Things worth knowing before teaching from these:**
- The BFS comparison came out nearly equal (17 vs 18 ms for 640,000 cells). The deck says so
  and uses it to make the point that the algorithm and the boxes dominate.
- `PriorityQueue` prints `[5, 10, 20, 30, 40]` for the values used, which happens to be sorted;
  the point of the slide is the **leaving** order (smallest first), not the print.
- JUnit and JMH are typed listings marked "Not run here"; they need dependencies that the
  runner does not fetch.
- `Palindrome` ignores case, spaces and punctuation; `"Küçük"` is a palindrome.
